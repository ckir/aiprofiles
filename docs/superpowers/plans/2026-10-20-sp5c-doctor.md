# SP5c `doctor` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `agent-profile doctor` and `agent-profile <agent> doctor [<profile>]`, text and `--json`, as the
read-only report the approved design describes.

**Architecture:** A new module `src/doctor.rs` builds an ordered `Report` of `Check` records from an explicit
`Environment` (no hidden process state, so every check is unit-testable). `json.rs` and `output.rs` each gain
one renderer. `cli.rs` routes `doctor` as a `CommandWord`, before the root and configuration loads that every
other command performs, and maps the report to exit 0 or 5. Shared pieces the design reuses
(`agents` element views, `repositories` element view, executable status, per-platform directory search) are
extracted from their current call sites first, with no behaviour change.

**Tech Stack:** Rust 1.99 (edition 2024), `serde`/`serde_json` (already dependencies), `tempfile` in tests,
cargo-nextest via `just`.

**Spec:** `docs/superpowers/specs/2026-10-20-sp5c-doctor-design.md` (APPROVED 2026-10-20). Section numbers
below (§N) are that document's. The SP5b envelope rules it inherits are
`docs/superpowers/specs/2026-10-19-sp5b-json-repositories-design.md` §3.1.

## Global Constraints

- Read-only: doctor creates, opens for writing, locks or removes nothing (§8). It never calls `config::locked`,
  `config::update`, `ensure_paths`, `Adapter::initialize` or `Adapter::plan`.
- No process spawn and no network from doctor (§1 non-goals, §8).
- No value read from the environment ever reaches either output (§5.3 `launch_environment`, §6).
- Exit codes: `0` no `fail`; `5` any `fail`; `2` usage errors before any check; `1` only when writing stdout
  fails (§4). Doctor never returns 3, 4 or 6.
- Closed token sets for `agent-profile/doctor/1` (§4, §6): statuses `pass info warn fail skip`; the twenty
  check ids of §5; `result` `ok fail`; `launch_environment.kind` `env env_file flag_dir flag_file`;
  `profile_path.kind` `dir file`.
- Every JSON member always present, `null` for absent; `schema` then `tool_version` first (SP5b §3.1).
- Debug builds register the `fake` adapter, so "every agent" in tests means `adapter::known_agents()`, which
  includes `fake`; never hard-code twelve.
- The repository gate is `just check` (fmt-check, clippy `-D warnings`, typos, shellcheck, line-citations,
  nextest, probe-tests, tools-doc-check, doc-check). Expected: exit 0. Run it as-is; add no stricter flags.
- Source comments must not cite another file by line number (`scripts/check-line-citations.sh`); cite the
  symbol instead.
- Permission tests follow `repo.rs`'s `an_unreadable_commondir_is_an_error`: apply the mode, probe whether it
  bites, and `eprintln!("skipped: ...")` + return when the user ignores permissions.

## Review Focus

1. **A fresh machine.** No application root, no `config.toml`, no repository, no agent installed: bare doctor
   must exit 0 and `<agent> doctor work` for an installed agent must exit 0 (§1 anti-goal). Pinned in Task 5
   (`fresh_host_is_green_in_both_forms`).
2. **`--repo` that does not exist.** Bare and targeted doctor must still print the host and agent records,
   `repository` `fail`, `resolution` `skip` (no explicit profile), exit 5, never exit 4. Pinned in Task 5
   (`missing_repo_is_a_fail_record_not_an_error`).
3. **A broken `config.toml` plus `--json`.** One valid JSON document on stdout, `config` `fail`, one `skip`
   per dependent id, exit 5, stderr empty. Pinned in Task 5 (`invalid_config_still_prints_one_document`).
4. **Non-UTF-8 and odd names in `profiles/`.** A non-UTF-8 entry and a dot entry must not panic the twin scan
   or the listing. Pinned in Task 2 (`case_twins_ignores_non_utf8_and_keeps_dot_entries`).
5. **Doctor agrees with the launch it predicts.** A file at `profiles/<p>`: doctor `fail` AND the launch
   exits 4, in one test; a symlink there to a real directory: doctor not `fail` AND the launch exits 0.
   Pinned in Task 5 (`profile_path_verdict_matches_the_launch`).

```rust
pub enum Status { Pass, Info, Warn, Fail, Skip }            // + fn token(self) -> &'static str
pub enum CheckId {                                           // + fn token(self) -> &'static str (snake_case of the name)
    Platform, AppRoot, AppRootWritable, Config, ConfigAgent, ProfilesDir, CaseTwins, DefaultProfile,
    Repository, Mapping, MappingAgent,
    Executable, RepositoryLocalExecutable, Support,
    Resolution, Profile, ProfilePath, LaunchEnvironment, ConflictingOption, Capability,
}
pub struct Check {
    pub id: CheckId,
    pub agent: Option<&'static str>,
    pub subject: Option<String>,
    pub status: Status,
    pub message: String,
    pub data: serde_json::Value,                              // Value::Null when the id has no data
}
pub struct Environment<'a> {
    pub root: std::result::Result<AppRoot, String>,           // AppRoot::resolve(), error rendered with Display
    pub path_var: Option<&'a OsStr>,
    pub cwd: &'a Path,                                        // the process's current directory
    pub start: &'a Path,                                      // cwd, or cwd.join(--repo)
    pub is_set: &'a dyn Fn(&str) -> bool,                     // whether an environment variable is set
}
pub enum Target { Host, Agent { agent: AgentId, profile: Option<String> } }
pub struct Report {
    pub agent: Option<AgentId>,
    pub profile: Option<ProfileName>,                         // the profile the agent form examined
    pub repository: Option<PathBuf>,
    pub checks: Vec<Check>,
}
impl Report { pub fn failed(&self) -> bool; pub fn count(&self, status: Status) -> usize; }
pub fn run(target: &Target, env: &Environment<'_>) -> Report;
```

`run` in this task emits §5.1 and §5.2 records only (Task 3 appends the per-agent ones). Skips follow §4's
table and its one-`skip`-record rule exactly; `skip` messages are `"skipped: <dependency token> failed"`.

Data objects (§6), as `serde_json::json!`:
`platform` `{"os","arch"}`; `app_root`, `app_root_writable`, `config` `{"path","exists"}`; `profiles_dir`
`{"path","exists","profiles","ignored"}` (`profiles`/`ignored` `null` on failure); `case_twins`
`{"names":[a,b]}`; `mapping` = `serde_json::to_value(json::repository_view(entry))`; every other §5.1/§5.2 id
`null`.

Decisions the design leaves to this plan:
- `profiles_dir` failure subject: if `fs::read_dir(profiles_dir)` itself fails, the profiles directory (and
  the §4 dependency row applies); otherwise the first profile directory, in byte order of name, whose
  `read_dir` fails (the row does not apply). The message carries `list_profiles`' error text.
- `case_twins`: names are every UTF-8 entry name of `profiles/` (dot entries included, non-UTF-8 skipped,
  any entry type, as `config::check_case_twins` does); a pair is `a < b` bytewise with
  `a.eq_ignore_ascii_case(b)`; records in `(a, b)` order. Three mutual twins give three records.
- `mapping_agent`: one `warn` per `(entry, agent)` with `AgentRef.known == false`, entries in stored-key
  order, agents in `BTreeMap` order; subject `"<key> <agent>"`.
- `config_agent`: `Config` exposes `configured_agents()`; an id not in `adapter::known_agents()` is `warn`.
- `repository`: `repo::discover(env.start)`; subject `env.start`; `Report.repository` is the root or `None`.

  `"sets <NAME> to <path>"` plus `"; already set in this environment, the launch replaces it"` when set; for
  the flag kinds `mechanism.sentence_for(target)`.
- `profile_path` data: `{"path","kind","exists","mode"}`; `mode` = `format!("{:o}", mode & 0o7777)` on Unix.
- `capability`: records only for claims whose state is not `Supported`, in `Capability::ALL` order; subject
  is the `json::capability_token`; message `"<state label>: <basis>"`.
- `conflicting_option`: subject `spelling()`; one per entry of
  `metadata.conflicts.iter().chain(metadata.mechanism.conflict_option())`, the exact set `adapter::check_conflicts`
